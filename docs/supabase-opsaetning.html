Du skal bruge en browser, en GitHub-konto (nemmeste login til Supabase) og filerne i kompudv. Sæt flueben ved hvert trin undervejs — det huskes i browseren, så du kan lukke siden og vende tilbage.

Om skærmbillederne

Supabase justerer deres dashboard løbende. Menunavnene herunder passer pr. august 2026 — hedder en knap noget lidt andet, ligger den næsten altid samme sted.

Trin 01

Opret konto og projekt

  1. Gå til supabase.com → Sign in → log ind med GitHub.
  2. Klik New project.
  3. Udfyld felterne:
    • Organization — vælg din egen, eller opret en (fx CAE).
    • Project name — kompudv
    • Database Password — klik Generate a password og gem den i en password-manager. Du får den ikke at se igen. Appen bruger den ikke — kun direkte databaseadgang gør.
    • Region — se advarslen nedenfor.
    • Pricing plan — Free.
  4. Klik Create new project. Der går 1–2 minutter, mens databasen provisioneres.
Kan ikke ændres bagefter

Vælg en EU-region, fx Central EU (Frankfurt). Regionen er GDPR-kritisk, og den kan ikke skiftes senere — kun ved at oprette et helt nyt projekt og flytte data.

Trin 02

Kør databaseskemaet

  1. Venstre menu → SQL Editor → New query.
  2. Åbn kompudv/supabase-schema.sql, kopiér hele indholdet og indsæt det i editoren.
  3. Klik Run (eller Ctrl + Enter).
  4. Forventet svar: Success. No rows returned

Hvad skemaet oprettede

ObjektFormål
Tabel profilesNavn og is_admin-flag pr. bruger
Tabel competencesSelve kompetenceregistreringerne
Funktion is_admin()Bruges af sikkerhedsreglerne
Trigger on_auth_user_createdOpretter automatisk en profil, når en bruger oprettes
Row Level SecuritySikrer at en bruger kun ser sine egne data, og at en admin ser alles
Kontrollér

Venstre menu → Table Editor. Du skal se profiles og competences, begge tomme.

Trin 03

Hent URL og nøgle

  1. Klik tandhjulet Project Settings nederst i venstre menu → API.
  2. Kopiér Project URL — formen er https://abcdefghijkl.supabase.co
  3. Kopiér den offentlige nøgle. Nyere projekter kalder den Publishable key (sb_publishable_…), ældre anon / public (en lang eyJhbGci…-streng). Begge virker med appen.
Tag ikke denne

service_role / secret key omgår al sikkerhed i databasen. Den må aldrig lægges i frontend-kode eller committes.

Trin 04

Sæt nøglerne ind i appen

Åbn kompudv/js/config.js og erstat placeholder-værdierne:

js/config.js
export const SUPABASE_URL = "https://abcdefghijkl.supabase.co";
export const SUPABASE_ANON_KEY = "sb_publishable_xxxxxxxxxxxx";
export const ADMIN_UNLOCK_PASSWORD = "Superadmin";

Filen må gerne committes. Den offentlige nøgle er designet til at ligge i frontend-kode — beskyttelsen ligger i Row Level Security, ikke i at nøglen holdes hemmelig.

Trin 05

Auth-indstillinger

E-mailbekræftelse

Gå til Authentication → Sign In / Providers → Email.

  • Til test: sæt Confirm email til off og gem. Så kan du oprette en bruger og logge ind med det samme.
  • Til drift: Confirm email on, og kobl en rigtig SMTP-server på under Project Settings → Authentication → SMTP Settings — fx AU's mailserver.
Hvorfor slå den fra under test

Supabases indbyggede mailserver er kraftigt rate-limited — få mails i timen — og mails ender ofte i spam. Det gør test unødigt langsomt.

URL-konfiguration

Gå til Authentication → URL Configuration:

  • Site URL — http://localhost:5173 mens du udvikler.
  • Redirect URLs — tilføj http://localhost:5173/** og senere https://jxrgen.github.io/kompudv/**

Disse bruges til bekræftelses- og password-nulstillingslinks.

Trin 06

Start appen lokalt

ES-moduler virker ikke fra file://, så der skal en lille webserver til:

PowerShell
cd C:\claude\kompetenceudvikling\kompudv
python -m http.server 5173

Åbn derefter localhost:5173.

Hvis python åbner Microsoft Store

Installér Python derfra, eller brug VS Code-udvidelsen Live Server (højreklik på index.html → Open with Live Server). Live Server bruger typisk port 5500 — brug så den i Site URL i stedet.

Trin 07

Opret din bruger og bliv admin

  1. I appen: Opret konto → navn, AU-mail, password på mindst 8 tegn.
  2. Log ind. Gem en testregistrering og se, at den kommer på listen.
  3. Gør dig til admin — SQL Editor → New query:
SQL
update public.profiles set is_admin = true
where id = (select id from auth.users where email = 'jho@cae.au.dk');

Forventet: Success. 1 row(s) affected. Står der 0 rows, er mailen stavet forkert — tjek den under Authentication → Users.

  1. Tilbage i appen: genindlæs siden — admin-status hentes ved login.
  2. Klik 7 gange på det blå app-ikon øverst til venstre, skriv Superadmin, klik Lås op.
  3. Vælg en bruger i listen → Eksportér CSV.
Trin 08

Kontrollér at sikkerheden virker

Kør denne test, før der kommer rigtige data i systemet.

  1. Opret bruger nr. 2 — fx din.mail+test@au.dk, plus-adressering virker.
  2. Log ind som bruger 2 og opret en registrering.

Bruger 2 skal opføre sig sådan

  • Kan kun se sin egen registrering — ikke din.
  • Kan ikke komme ind i admin. 7 klik + Superadmin skal give beskeden om manglende rettigheder.
Hvad testen beviser

Opfører den sig sådan, er Row Level Security aktiv — og det delte admin-password er ikke i sig selv nok til at nå andres data.

Fejlfinding

SymptomÅrsag og løsning
“Supabase er ikke konfigureret endnu”js/config.js har stadig placeholders — eller browseren har cachet den gamle fil. Hard-reload med Ctrl + F5.
Blank side, konsolfejl om importSiden er åbnet som file://. Brug en webserver, se trin 06.
Invalid API keyForkert nøgle, eller URL og nøgle stammer fra to forskellige projekter.
“E-mailen er ikke bekræftet endnu”Confirm email er slået til. Slå den fra, se trin 05, eller klik linket i mailen.
Bruger oprettet, men ingen profil-rækkeTrigger’en kørte ikke. Kør supabase-schema.sql igen og opret brugeren på ny.
“Din bruger har ikke admin-rettigheder”is_admin ikke sat, eller siden ikke genindlæst efter SQL-opdateringen.
Projektet står som PausedGratis-projekter pauses efter ca. 7 dages inaktivitet. Genstart det fra dashboardet.
Før drift

GDPR — hvad der mangler

Appen behandler personoplysninger om medarbejdere: navn, e-mail og aktiviteter. Følgende skal på plads, før den tages i brug med rigtige data.

  • Databehandleraftale mellem Aarhus Universitet og Supabase. Supabase har en standard-DPA.
  • Skriftlig bekræftelse på at data og backups forbliver i EU.
  • Formål, retsgrundlag og opbevaringsperiode beskrevet over for medarbejderne.
  • Det delte admin-password erstattet af egentlige roller.
  • AU IT og jura involveret inden produktionssætning.
Bemærk

Punkterne ovenfor blokerer ikke test og udvikling med opdigtede data. De blokerer for at lægge rigtige medarbejderoplysninger ind.
